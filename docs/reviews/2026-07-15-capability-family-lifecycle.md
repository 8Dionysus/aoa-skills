# Capability-family lifecycle review — 2026-07-15

Status: admitted owner review, not central proof or permanent promotion.

## Scope

The review compared the former 57-skill surface, no-skill behavior, and the
seven consolidated family bundles through manually inspected, read-only cases.
It covered positive and negative applicability, direct and retrieved selection,
isolated and coexisting installation, owner-boundary errors, clean-host prompt
visibility, package inspection, and task-local DAG composition.

Behavioral comparisons used a current strong Codex model. Codex CLI 0.144.4
was also used for clean prompt-visible catalog checks. Gemini CLI 0.49.0 was
available for isolated package installation and catalog inspection, but not for
an authenticated isolated behavioral comparison. Raw prompts, traces, fixture
copies, task-local plans, and session identifiers remain outside the repository.

## Findings

### `aoa-decision`

- Easy lookup remained achievable without the skill.
- In held-out `record` work, the bundle preserved missing alternatives,
  rationale, consequences, and validation data as missing and stopped
  `blocked_missing_input`; the no-skill arm invented plausible material.
- In `correct` work, the bundle rejected hand-editing a generated view when its
  owner builder contract was absent.
- An ordinary typo request did not activate the bundle.

Disposition: retain as the only advertised challenger with
`pilot-verified/challenger` posture. This is not a claim of universal lift or an
`active/healthy` promotion.

### Six other bundles

Engineering shape, eval, verification, knowledge stewardship, session harvest,
and session recovery selected the intended modes and generally respected their
stop lines, but did not add a necessary correct conclusion over no-skill arms.
They also increased prompt/tool context; one harvest arm split a coherent owner
pattern less usefully than the baseline.

Disposition: keep their procedures and semantic modes for explicit research,
deep retrieval, and DAG composition, but leave all six
`evaluated/degraded/deferred`. Do not expose them in the normal install profile.

### 2026-07-16 owner-instance currentness challenger

A real post-merge projection failure selected a stale conventional checkout,
and a separate current `aoa-routing` artifact still described a retired skill
from stale semantic input. These failures justified challenging the
`authority-map` mode with an explicit owner-instance currentness revision.

Two manually inspected read-only comparisons covered the retired skill's fate
across owner checkouts and a branch-current routing artifact whose upstream
skill meaning had changed. The first comparison included no-skill, current,
candidate, and coexistence arms; the second compared current and candidate on a
bounded different owner pair.

The current `0.1.0` procedure and the candidate both reached the required owner,
instance, claim-limit, and stale-input conclusions. The no-skill arm also
reached the first conclusion. The candidate produced no unique correct outcome,
was not cheaper in either comparison, and consumed several times more input in
the second. Coexistence did not falsely activate the neighboring stats bundle,
but carried substantial additional context cost.

Disposition: reject the currentness expansion and retain
`aoa-knowledge-stewardship@0.1.0` as `evaluated/degraded/deferred`. Do not create
a separate currentness skill, permanent eval suite, or generic validator from
these cases. Keep mutation refusal and source-currentness guards with the owner
tools that can enforce them, and repair stale routing ingestion in
`aoa-routing`. Repeat only after a distinct recurring failure or material
model/runtime drift. Raw prompts, traces, task-local plans, temporary homes, and
session identifiers remain outside the repository.

### Capability graph and DAG

Manual planning established real ABI flow for evaluation, recovery, harvest,
engineering/decision/verification, ATM10, Abyss, and Titan compositions.
Missing inputs, conflicting decision modes, and unbound infrastructure,
runtime-transition, thread-turn, and human gates fail closed. A retrieval trial
also exposed generic session language incorrectly outranking a Titan adapter;
project-scoped candidates now receive a bounded penalty when the request lacks
their project marker, while project-specific queries remain discoverable.

Disposition: retain semantic capabilities even when they do not justify a
standalone advertised skill. Tree discovery, typed relations, and task-local
DAG execution solve different problems.

### Host behavior

- The normal package contains only `aoa-decision` and presents that single AoA
  skill in a clean Codex and Gemini catalog.
- The research/source package transports all seven. Codex honors its OpenAI
  adapter and initially exposes only `aoa-decision`; Gemini accepts the same
  Agent Skills packages but enables all seven because OpenAI invocation policy
  is not portable.

Disposition: `repo-default` is the cross-host normal profile.
`repo-capability-sources` is an explicit laboratory/source profile, never a
portable deferred-visibility policy.

## Attribution limits

The cases were deliberately legible and used one strong behavioral model. A
weaker model, noisier repository, changed host router, new owner contract, or
different tool surface may change relative value. Installation parity does not
establish behavioral parity. These limits justify challenger/deferred posture,
not speculative promotion.

## Durable follow-up

Repeat manual comparison after material model, host, owner-contract, or
workflow drift, or when harder real work demonstrates a recurring gap. Admit a
new suite or validator only when those trials expose a stable long-lived
invariant and a named consumer; otherwise keep the evidence session-local.
