# Manual example

## Scenario

A repository change may need durable evaluation, but no exact evidence surface
has been selected.

## Select

- name the invariant and acceptance target;
- inspect the repository-local eval route and the stronger proof owner;
- compare exact command, prerequisites, artifact, freshness, and proof class;
- return `exact`, `partial`, or `no-fit` with rejected alternatives.

Do not run a nearby broad gate merely because it is available.

## Apply

When an exact fit exists, record the repository revision, model/host/tools,
command, expected artifact, accepted exits, and effect posture. Run only that
surface and inspect the result manually. Exit zero is not sufficient if the
named invariant or artifact is absent.

## Propose

Only a recorded no-fit may enter `propose`. Produce the smallest owner-local
intake or suite-design candidate, list the manual cases that must precede a
durable validator, and route central proof decisions to `aoa-evals`.

Session-memory evidence may support the proposal when explicitly reviewed, but
it is optional and never becomes repository truth.
