# Extract reviewed donor units

### Mode: extract

Use after a session artifact or bounded recap is explicitly reviewed and the
question is what reusable units, if any, emerged—not merely what happened.

1. Record the session goal, closure/review posture, evidence boundary, touched
   owners, uncertainty, and requested posture (`classify-only`, `draft-stub`, or
   `proposal`).
2. Inventory checkpoint, closeout, ledger, and handoff hints. Disposition each
   as accepted, rejected, stale, cross-session, contaminated, or unresolved
   before it can influence a candidate.
3. Extract bounded moves, laws, checklists, structures, routes, proof patterns,
   recall patterns, or stable manual processes—not themes or topics.
4. Split mixed units until each has one primary reuse kind, owner shape, input
   and output posture, evidence anchors, and nearest wrong target.
5. Mint a session-local candidate ref only after reviewed evidence supports the
   unit. Preserve cluster refs and supersession/drop relations when supplied.
6. Keep weak, mixed, early, or unresolved material as residue/hold without
   forcing a candidate ID.
7. Return the next typed handoff separately: classify, promote,
   automation-opportunity, branch, recovery, progression, memo-writeback, or
   no durable artifact.

Return a `harvest-packet` containing accepted units, hint dispositions,
unresolved residue, evidence refs, owner hypotheses, rejected targets, and
handoffs. Receipts may be suggested only through an existing stats owner
contract; they are never required output or authority.
