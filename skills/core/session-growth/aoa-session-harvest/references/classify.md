# Classify one reusable candidate

### Mode: classify

Use when exactly one reviewed candidate is isolated and its durable object kind
and owner are not yet settled.

1. Require recurrence/reuse evidence, stable input and output posture, proof
   posture, reversibility, risk, approval sensitivity, and independent
   composition value. Missing fields yield defer, not invention.
2. Compare `procedure/skill`, `workflow/playbook`, `tool`, `guard`, `adapter`,
   `eval`, `memo-candidate`, `agent/orchestrator surface`, `quest/hold`, and
   `no durable artifact` by their actual owner/effect contracts.
3. Keep domain meaning with the domain owner. Routing and KAG are derived
   consumers, never first-authoring targets for another owner's meaning.
4. Reject the nearest plausible wrong kind explicitly. One good run, repeated
   discussion, telemetry count, or an existing filename does not prove fit.
5. Return `defer`, `reject`, or `propose` plus owner, input/output ABI, next
   artifact, acceptance needs, and handoff. Do not author or promote it.

The output is `candidate-object-classification`; it is not downstream owner
acceptance and does not silently continue into promotion or automation.
