# Preserve continuation branches

### Mode: branch

Use when reviewed evidence supports several materially different next moves.

1. Separate real branches from cosmetic implementation variants.
2. For each branch record likely gain, cost, risk, first owner, prerequisites,
   effect, difficulty/control posture, handoff ABI, and stop condition.
3. Keep automation and non-automation branches side by side when that is the
   real choice. Preserve a hold/re-anchor option under meaningful uncertainty.
4. A suggested default is advisory and must not hide alternatives.
5. When one route becomes selected, anchored, output-named child work, stop and
   hand the launch gate to `aoa-summon`; do not delegate from fork analysis.

Return `continuation-branch-cards`. They are choice evidence, not routing,
scheduling, quest-board, or runtime authority.
