# AGENTS.md

Guidance for `skills/project/`.

## Purpose

`project/` holds owner-family overlay skills. Overlays adapt portable AoA skill
practice to a named project context without moving that project's authority into
`aoa-skills`.

## Read First

1. `../AGENTS.md`
2. this file
3. the nearest family `AGENTS.md`
4. `../README.md`
5. the target bundle `SKILL.md` and `techniques.yaml`
6. `../../mechanics/boundary-bridge/docs/OVERLAY_SPEC.md`
7. matching `../../mechanics/boundary-bridge/overlays/<family>/PROJECT_OVERLAY.md`
   when present

## Local Law

- Keep overlays thin.
- Name local paths, approvals, commands, and stop-lines only as bounded
  adaptation.
- Do not claim final runtime, memory, role, repo, or owner-project truth.
- Keep the base skill relationship visible in bundle wording, examples,
  checks, generated overlay readiness, and mechanics overlay docs.

## Validation

After overlay changes, run the bounded source/export flow from `../AGENTS.md`
and validate overlay readiness through the generated catalog path.
