# Checkpoint Roadmap

## Current Contour

Checkpoint owns checkpoint-note capture, closeout bridge posture, and the
boundary between provisional checkpoint evidence and reviewed closeout action.
It does not own final harvest, progression, quest, memory, proof, or owner
truth.

Active surfaces include `docs/CHECKPOINT_NOTE_PATH.md`,
`skills/core/session-growth/aoa-commit-growth-seam/SKILL.md`,
`skills/core/session-growth/aoa-checkpoint-closeout-bridge/SKILL.md`,
`schemas/session_checkpoint_note.schema.json`, and provenance links to
growth-cycle kernel maturity.

## Next Work

- Keep checkpoint-aware and reviewed owner-status follow-through visible after
  releases instead of burying it in changelog prose.
- Decide whether reviewed checkpoint snapshots need a local route or should
  remain SDK/runtime evidence.
- Decide whether SDK checkpoint-control surfaces need only provenance links or
  a narrow bridge doc here.
- Keep session-growth maturity in growth-cycle unless checkpoint-specific
  receipt routing changes.
- Keep method-growth candidate lineage out of checkpoint except for exact
  handoff references.

## When Time Comes

- Add a checkpoint route only when repeated closeout handoffs need the same
  inspectable source path.
- Promote checkpoint-derived candidates only after reviewed closeout evidence
  re-reads them through donor harvest, progression lift, and quest harvest in
  that order.
- Add validation only for the checkpoint contract itself, not for every
  downstream owner action.

## Out Of Scope

- Storing live runtime notes as source truth.
- Moving core session-growth skill meaning into checkpoint.
- Claiming final harvest, progression, quest, memory, proof, or owner truth from
  checkpoint notes alone.
