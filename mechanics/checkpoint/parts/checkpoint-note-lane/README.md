# Checkpoint Note Lane

## Use When

Use this part when a meaningful checkpoint needs to preserve provisional growth
candidates, evidence refs, owner hints, `cluster_ref`, status posture, and
promotion conditions before reviewed harvest.

## Do Not Use When

Do not use this part to emit donor harvest verdicts, progression packets, quest
verdicts, automation authority, memory canon, hidden mutation, `candidate_ref`,
or final owner truth.

## Route Check

- Is this a meaningful checkpoint signal?
- Is the note append-only and lower-authority?
- Are candidate clusters still provisional?
- Does the note avoid `candidate_ref`?
- Is any promotion recommendation explicit and bounded?

## Active Outputs

- checkpoint history
- candidate clusters
- evidence refs
- owner hints
- review posture
- promotion recommendation
- defer reasons and next owner moves

## Next Route

When reviewed closeout is ready, route to
[Closeout Bridge Boundary](../closeout-bridge-boundary/README.md). If the note
is promoted as a reviewed snapshot, route it to the explicit owner such as
`Dionysus`.
