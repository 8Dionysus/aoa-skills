# Agon Roadmap

## Current Contour

Agon owns bounded skill-binding and epistemic candidate bridges for Agon-shaped
workflow pressure. It does not define center Agon law, and generated candidate
requests remain `requested_not_landed` until normal skill review accepts them.

Active surfaces include `parts/workflow-candidate-bridge/`,
`parts/candidate-validation-gate/`, `parts/epistemic-candidate-boundary/`,
`generated/agon_skill_binding_candidates.min.json`,
`generated/agon_epistemic_skill_candidates.min.json`, and the related build and
validation scripts.

## Next Work

- Keep package-local legacy snapshots narrow and source-preserving.
- Plan a separate generated/config schema migration if historical fields still
  shape active candidate payloads.
- Add a package-local artifact topology note only if schemas, generated files,
  scripts, and tests become hard to scan from the package card.
- Review whether any requested-only candidate has enough technique traceability,
  test proof, and owner acceptance to become a real skill slice.
- Keep recurrence manifests observation-only when their paths change.

## When Time Comes

- Promote a candidate only through the normal skill review path with pinned
  technique lineage and explicit trigger boundaries.
- Route recurring Agon scenario composition to `aoa-playbooks`; keep this
  package focused on skill-layer candidate posture.
- Split a new Agon part only when one bridge starts mixing source candidate
  capture, validation gates, and generated projection maintenance.

## Out Of Scope

- Converting every lawful move into a skill.
- Treating recurrence pressure as activation authority.
- Letting Agon package language define center Agon law.
