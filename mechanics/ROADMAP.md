# Mechanics Roadmap Router

This file routes future skill-layer pressure to the mechanic that owns it. It
is not the repo's single backlog, not a release ledger, and not a second source
of skill meaning.

Program movement is distributed. The nearest package `ROADMAP.md` owns the
next contour for its mechanic, while `mechanics/README.md` names the package
map and package cards name local entry routes.

## Current Contour

The public foundation already has coherent docs, generated governance readouts,
validated skill bundles, pinned technique traceability, evaluation fixtures,
release identity, and active mechanic packages.
Shared mechanics-level owner-request receipts stay in
`mechanics/OWNER_REQUEST_RECEIPTS.md`; package roadmaps handle package-local
future movement.

The current work is no longer baseline scaffolding. It is owner clarity:

- `audit` owns public-surface, evaluation, governance backlog, review-record,
  and proof-readout pressure.
- `boundary-bridge` owns overlays, source-owned bridge contracts, tiny-router
  compression, OpenAI/Codex/MCP disclosure, and downstream-consumption seams.
- `release-support` owns portable export, install profiles, local adapters,
  runtime seams, release manifests, staged bundles, ZIP handoff, and packaging
  smoke.
- `method-growth` owns maturity, promotion, default-reference rationale,
  owner-status landing, candidate lineage, and adoption evidence.
- `growth-cycle` owns the session-growth kernel, adaptive orchestration, and
  reviewed-session harvest posture.
- `checkpoint` owns checkpoint-note capture, closeout bridge posture, and
  checkpoint-to-reviewed-closeout boundaries.
- `questbook` owns quest source/index law, quest dispatch projection, and
  `aoa-quest-harvest` posture; the public index is `../QUESTBOOK.md`.
- `agon` owns bounded Agon skill-binding candidate bridges and keeps all
  generated candidate requests `requested_not_landed` until review lands them.
- `recurrence` owns observation and recurrence-decision closure, not automatic
  activation.
- `rpg` owns ability and loadout reader posture, not runtime inventory.
- `antifragility` owns fallback, pruning, collision stress, and the risk guard
  ring.
- `experience` owns workflow experience contracts and keeps non-landed owner
  requests below source truth.

## Update Rule

When a change lands, update the owner package that future agents must read next:

- generated public, evaluation, governance, review, or promotion evidence:
  `audit/ROADMAP.md`
- overlays, bridge contracts, tiny-router, MCP/OpenAI/Codex wiring, or
  downstream consumption: `boundary-bridge/ROADMAP.md`
- release manifests, export/import, staged bundle, ZIP, profile install, local
  adapter, runtime seam, or support resources: `release-support/ROADMAP.md`
- maturity, default-reference, owner-status, candidate lineage, adoption, or
  promotion path: `method-growth/ROADMAP.md`
- session-harvest family, project-core kernel, adaptive orchestration, or
  reviewed-session artifacts: `growth-cycle/ROADMAP.md`
- checkpoint-note flow or closeout bridge: `checkpoint/ROADMAP.md`
- durable quest obligation, quest catalog, dispatch projection, or
  `aoa-quest-harvest` verdict posture: `questbook/ROADMAP.md` and, when public
  bands change, `../QUESTBOOK.md`
- Agon candidate generation, validation, or recurrence observation:
  `agon/ROADMAP.md`
- recurrence manifests or component refresh decision closure:
  `recurrence/ROADMAP.md`
- ability/loadout reading over skill bundles: `rpg/ROADMAP.md`
- risk ring, collision stress, fallback, pruning, or public-share safety:
  `antifragility/ROADMAP.md`
- workflow experience examples, contract notes, or active owner-request
  experience posture: `experience/ROADMAP.md`

If more than one package is touched, update only the packages whose future
movement actually changed. Do not duplicate the same backlog text across
packages.

## When Time Comes

- Add a new mechanic only when an existing package would become less clear by
  owning the pressure.
- Add package-local validation when repeated manual checks become the normal
  route.
- Promote a generated readout only after the source package names what the
  readout proves and what it cannot author.
- Split downstream bridge work only when source-owned meaning and consumption
  order can be verified from `main` without PR folklore.
- Open broader export/import ergonomics only after the staged directory, ZIP
  handoff, preflight inspection, bundle README, and release smoke stay green.

## Out Of Scope

- Do not store package task inventories here.
- Do not turn release history into roadmap authority.
- Do not treat generated readouts as source truth.
- Do not move skill meaning out of `skills/**/SKILL.md`.
- Do not make `aoa-skills` the owner of AoA center doctrine, downstream runtime
  truth, playbook scenario canon, memory truth, or eval authority.
