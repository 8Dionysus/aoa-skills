# Review Decision Closure

## Use When

Use this part when skill beacons need a bounded review decision rather than a
silent activation behavior change.

## Do Not Use When

Do not use this part to suppress broad classes of future signals, accept owner
work, prove readiness, mutate manifests, or promote a skill from one anecdotal
repeat.

## Route Check

- Is this a genuine miss, explicit-only restraint, collision avoidance,
  unavailable host support, or intentional non-use?
- Is the decision `accept`, `suppress`, or `route away`?
- Is a suppress decision narrow in reason and scope?
- Does an accept decision point to a concrete follow-through surface?

## Active Outputs

- review decision posture
- narrow suppression reason or accepted follow-through cue
- target surface for trigger-eval, description, bundle, applicability-map, or
  owner follow-through
- no automatic activation behavior change

## Next Route

Use `suppress` only with a narrow reason and scope. Use `accept` to point at
trigger-eval, description, bundle, or applicability-map follow-through rather
than silently changing activation behavior.
