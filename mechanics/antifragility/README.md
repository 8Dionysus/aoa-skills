# Antifragility

This package owns the `aoa-skills` side of antifragility-shaped risk posture:
fallback authoring, via negativa pruning, and trigger-collision stress around
existing skill bundles.

Antifragility here is thinner than the center mechanic in `Agents-of-Abyss`.
The center owns doctrine, via negativa law, anti-authority posture, fragile
pattern routing, and owner-request packets. This repo owns local movement
grammar that keeps skill workflows bounded under stress.

## Mechanic card

Status: `landed-local-risk-posture-start`.

### Trigger

Use this package when degraded-mode guidance, fallback authoring, skill pruning,
trigger-collision stress, or risk posture needs to constrain skill-layer
movement without changing canonical skill meaning.

### Local owns

This package owns skill-layer fallback authoring posture, via negativa pruning
checks, trigger-collision stress routing, risk-perimeter cues, and stop-lines
that keep resilience pressure below skill canon and owner-local execution.

### Stronger owner split

`Agents-of-Abyss` owns center antifragility doctrine. `aoa-evals` owns proof and
regression verdicts. `aoa-routing` owns routing behavior. `aoa-playbooks` owns
recurring stress choreography. Runtime behavior and rollback execution belong to
`abyss-stack` and owner projects. Release and installation posture belongs to
release-support or experience routes until a narrower owner-local slice proves
otherwise.

### Inputs

- skill authoring pressure around degraded behavior or fallback posture
- pruning, merge, suppression, quarantine, deprecation, or removal candidates
- trigger or description collision stress evidence
- risk-ring, policy, generated eval, support-resource, or runtime guardrail
  readouts

### Outputs

- fallback authoring cue
- via negativa pruning route
- collision-stress follow-through route
- risk-perimeter note
- owner handoff cue
- no skill truth, proof verdict, deletion approval, runtime rollback, routing
  authority, release approval, or owner acceptance

### Must not claim

- canonical skill rewrite
- deletion theater
- unsafe rollback
- proof verdict
- runtime self-healing
- routing sovereignty
- release approval
- owner-local cleanup authority
- automatic skill promotion

## Boundary

Antifragility can constrain how skill-layer stress becomes authoring posture,
pruning pressure, and collision evaluation. It does not rewrite `SKILL.md`,
delete bundles, execute rollback, prove repairs, own runtime guardrails, or
accept cleanup for another repository.
