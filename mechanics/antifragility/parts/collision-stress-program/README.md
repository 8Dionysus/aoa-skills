# Collision Stress Program

## Use When

Use this part when timeout chaos, source-of-truth conflict, one-off incident
language, or project-overlay pressure needs additive trigger-collision stress
coverage.

## Do Not Use When

Do not use this part to add a runtime layer, override explicit-only invocation,
declare routing sovereignty, or treat one stress prompt as proof of a skill
boundary.

## Route Check

- Does the stress prompt belong to an existing collision family or trigger
  class?
- Should the expected behavior be skill invocation, no invocation, or manual
  invocation required?
- Should `aoa-source-of-truth-check` win because stress docs, runbooks, and
  receipts disagree about authority?
- Are downstream tiny-router cases inheriting the same boundary instead of
  improvising a new lane?
