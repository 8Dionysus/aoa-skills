# Via Negativa Pruning

## Use When

Use this part when a skill or skill-shaped proposal may need to stay intact,
merge, move, suppress, quarantine, deprecate, or be removed.

## Do Not Use When

Do not use this part to delete source history, bypass review, remove owner-local
truth, or collapse a real execution workflow just because it resembles a
technique.

## Route Check

- Does the skill own a bounded job, or mostly paraphrase a technique?
- Does it add execution value beyond the underlying technique?
- Are trigger boundaries, outputs, risks, and verification clear?
- Could the pressure be an addendum, overlay, support resource, or technique
  route instead of a new skill?
- Is the workflow crossing owner boundaries without an explicit handoff?

## Active Outputs

- keep-intact cue
- merge or move candidate
- suppression, quarantine, deprecation, or removal cue
- owner handoff for accepted deletion or replacement
- no deletion approval by itself

## Next Route

Every surviving skill should remain necessary, bounded, and non-redundant.
Actual skill changes go through normal `skills/*/SKILL.md` review, generated
catalog validation, and owner-route checks.
