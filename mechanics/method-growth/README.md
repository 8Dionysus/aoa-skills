# Method-Growth

This package owns the `aoa-skills` side of the cross-project Method-growth
mechanic: reviewed candidate identity, first owner-status landing, one bounded
followthrough decision after `candidate_ref` exists, and explicit adoption
lifecycle posture for skill-layer uptake.

It keeps Growth Refinery lineage visible without turning it into seed truth,
final object truth, proof, memory canon, runtime activation, or downstream
owner acceptance.

## Mechanic card

Status: `landed-local-lineage-and-adoption-start`.

### Trigger

Use this package when reviewed donor harvest, checkpoint carry, reusable
session residue, or downstream skill uptake pressure needs an `aoa-skills`
method-growth route: `cluster_ref` carry, reviewed `candidate_ref`, first
owner-status landing, the next bounded followthrough verdict, explicit adoption
boundary, adoption receipt, retention/regression/retirement path, or
pattern-to-skill handoff.

### Local owns

This package owns the skill-layer candidate identity seam, owner-status landing
contract, governed followthrough contract, adoption lifecycle boundary, owner
decision and receipt route, retention/regression/retirement posture,
pattern-to-skill handoff route, local stop-lines, schema/example route, and
active part map for method-growth movement in `aoa-skills`. It also owns the
whole-family disposition grammar that makes one reviewed lifecycle decision
per current skill explicit without granting proof or promotion authority.

### Stronger owner split

`Agents-of-Abyss` owns center Method-growth law and growth-route vocabulary.
`aoa-sdk` owns provisional checkpoint and closeout carry before reviewed
donor harvest. `Dionysus` owns seed staging. `aoa-evals` owns proof verdicts.
`aoa-playbooks` owns recurring method choreography. `aoa-memo` owns durable
memory objects. `aoa-stats` owns derived summaries. Final owner repositories
own final object truth and local adoption.

### Inputs

- reviewed session artifact or donor-harvest packet
- provisional `cluster_ref`, owner hints, evidence refs, and status posture
- canonical donor-harvest skill references
- reviewed owner-landing schemas and examples
- route-followthrough decision schemas and examples
- adoption compatibility, owner decision, receipt, regression, retirement, and
  pattern adoption contract evidence

### Outputs

- candidate-lineage route for reviewed `candidate_ref`
- first reviewed owner-status landing bundle
- one bounded route-followthrough decision
- owner route, proof route, seed route, memory route, stats hint, or drop
  reason
- adoption compatibility report, owner decision, adoption receipt, regression
  case, retirement cue, or pattern adoption patch
- source-exact whole-family skill-effectiveness disposition review
- no seed, final object, proof, memory, playbook, or runtime truth by itself

### Must not claim

- `candidate_ref` from unreviewed residue
- `seed_ref` or `object_ref`
- owner acceptance
- proof completion
- memory canon
- route scheduling authority
- automatic skill promotion
- hidden assistant self-adoption
- adoption without local owner consent
- durable behavior change without rollback and retention evidence

## Boundary

Method-growth mechanics can make reviewed candidate and adoption movement
explicit. They do not accept the candidate for a downstream owner, replace the
canonical skill bundle that performs donor harvest, or approve durable adoption
without local owner consent.

Promotion pressure is a local review signal, not a shortcut.
Use [Promotion Pressure](docs/PROMOTION_PRESSURE.md) and
`generated/skill_promotion_pressure.md` to see which heavily used skills should
receive blocker repair, status review, canonical review, or overlay adoption
review next.
