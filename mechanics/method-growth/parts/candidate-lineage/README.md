# Candidate Lineage

## Use When

Use this part when a reviewed donor-harvest route is ready to mint
`candidate_ref` while preserving earlier lineage such as `cluster_ref`, owner
hypothesis, nearest wrong target, evidence refs, and status posture.

## Do Not Use When

Do not use this part for live checkpoint residue, vague theme clouds, seed
staging, proof verdicts, final owner objects, or routing-layer authorship.

## Route Check

- Has the session artifact been reviewed?
- Is the reusable unit bounded?
- Is there one owner hypothesis?
- Was the nearest wrong target considered honestly?
- Does the route reject `seed_ref` and `object_ref` here?

## Active Outputs

- reviewed `candidate_ref`
- carried `cluster_ref` when available
- owner hypothesis and owner shape
- nearest wrong target
- evidence refs
- status posture
- supersession, merge, or drop fields when known

## Next Route

After `candidate_ref` exists, route to
[Owner Status Landing](../owner-status-landing/README.md) or to a stronger
owner route named by the reviewed evidence.
