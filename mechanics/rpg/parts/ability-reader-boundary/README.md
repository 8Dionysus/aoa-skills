# Ability Reader Boundary

## Use When

Use this part when a skill ability card needs to summarize how an existing
skill bundle behaves as an executable ability.

## Do Not Use When

Do not use this part to change `SKILL.md`, introduce RPG lore as primary skill
meaning, override evaluation evidence, or turn one project overlay into a new
core ability.

## Route Check

- Which canonical skill bundle owns the meaning?
- Which technique, evaluation, portable-layer, adapter, overlay, or profile
  surfaces support the reader hint?
- Is the ability card clearly derived?
- Does choreography belong in `aoa-playbooks` instead?

## Active Outputs

- ability reader boundary
- evidence-ref cue
- generated companion route
- owner handoff cue
- no canonical skill change

## Next Route

Keep ability cards below `skills/**/SKILL.md`,
`skills/**/techniques.yaml`, evaluation surfaces, pack profiles, portable-layer
docs, adapter contracts, and overlay contracts. Route scenario choreography to
`aoa-playbooks`.
