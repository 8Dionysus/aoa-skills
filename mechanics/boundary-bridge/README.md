# Boundary Bridge

This package owns the `aoa-skills` side of crossing boundaries without moving
authority: technique-to-skill bridges, layer position, overlays, support-dir
bridges, MCP/OpenAI seams, and two-stage selection.

## Mechanic card

Status: `landed-local-route`.

### Trigger

Use this package when work touches layer boundaries, technique bridge metadata,
project overlays, downstream tiny-router inputs, MCP wiring, OpenAI metadata,
or support-dir bridge posture.

### Local owns

`aoa-skills` owns bridge contracts that keep skill bundles portable and
downstream overlays thin.

### Stronger owner split

`aoa-techniques` owns reusable practice truth. `aoa-routing` owns routing
policy. Downstream repositories own local overlay truth. Generated metadata is
a projection, not doctrine.

### Inputs

- bridge metadata or technique dependency pressure
- downstream overlay surface
- MCP/OpenAI wiring note
- tiny-router or support-dir bridge pressure

### Outputs

- explicit boundary contract
- owner route or generated feed hint
- no transfer of truth across repositories

### Must not claim

- routing sovereignty
- downstream owner acceptance
- generated metadata as doctrine
- identity collapse between base skill and project overlay
