# Boundary Bridge Roadmap

## Current Contour

Boundary-bridge owns skill-layer crossings: overlay contracts, source-owned
bridge meaning, tiny-router compression, local adapter disclosure, and
downstream-consumption seams. It keeps optional host wiring below source truth.

Active surfaces include `docs/BRIDGE_SPEC.md`, `docs/LAYER_POSITION.md`,
`docs/OVERLAY_SPEC.md`, `docs/TINY_ROUTER_COMPRESSION_BRIDGE.md`,
`docs/TWO_STAGE_SKILL_SELECTION.md`, `docs/CODEX_SKILL_MCP_WIRING.md`,
`mechanics/boundary-bridge/docs/CODEX_SKILL_MCP_WIRING.md`,
`docs/OPENAI_SKILL_EXTENSIONS.md`, `generated/overlay_readiness.md`, and live
overlay examples for `atm10-*` and `abyss-*`.

## Next Work

- Keep `v0.6` project-overlay maturity thin: repo-local commands, local
  authority, validation evidence, and no silent fork of public core meaning.
- Keep `atm10` and `abyss` under one discovered live-family contract; treat the
  second family as a transfer check, not a hierarchy.
- Plan source-owned bridge changes with explicit merge order and rerun policy
  before downstream repos consume new meaning from `main`.
- Tighten tiny-router references after generated surfaces rebuild.
- Decide whether live overlay family reviews need a package-local index only
  after parity starts becoming hard to scan.

## When Time Comes

- Add a third live family only if it clarifies the overlay contract.
- Promote bridge guidance into downstream repos only after source-owned meaning,
  generated readouts, and consumer update order are all named.
- Add a lane-local bridge registry when more than one downstream family needs
  the same acceptance or rerun choreography.

## Out Of Scope

- Runtime deployment truth, remote registry authority, and live downstream
  integration ownership.
- Turning MCP/OpenAI seams into mandatory host-runtime law.
- Moving overlay skill meaning out of `skills/`.
